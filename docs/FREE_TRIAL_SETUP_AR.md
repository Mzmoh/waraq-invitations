# تشغيل WARAQ كتجربة مجانية

هذه خطوات إعداد حسابَي الاستضافة بعد تأكيد عدم إنشائهما بعد. لا تنقل قاعدة بياناتك الحالية ولا ترفع مفاتيح إلى GitHub أو المحادثة. نبقي نسخة Node/SQLite الأصلية كما هي.

## 1. أنشئ مشروع Supabase للتجربة

1. افتح [لوحة Supabase](https://supabase.com/dashboard)، وسجّل الدخول بحسابك.
2. اختر مؤسسة بخطة **Free**، ثم **New project**. سمِّ المشروع `waraq-trial`، واحفظ كلمة مرور قاعدة البيانات عندك بصورة آمنة.
3. انتظر اكتمال الإنشاء. رابط صفحة المشروع يشبه `https://supabase.com/dashboard/project/PROJECT_REF`؛ يمكن مشاركته للمساعدة، أما كلمة المرور والمفاتيح فلا ترسلها هنا.
4. في **SQL Editor**، نفّذ ملفات هذا الفرع من `supabase/migrations` بالترتيب: `0001_trial.sql`، `0002_private_storage.sql`، `0003_catalog.sql`، `0004_performance.sql`، `0005_responsive_media.sql`، `0006_report_pagination.sql`. استخدم المشروع التجريبي الجديد الفارغ فقط. إذا ظهر خطأ فتوقف عند الملف وسجّل نصه بعد حذف أي أسرار.
5. تأكد أن حاوية `waraq-trial-private` خاصة، وأن `waraq_private` غير معرّض عبر Data API. لا تحتاج تفعيل Supabase Auth؛ WARAQ يحتفظ بنظام حساباته الحالي.
6. افتح **Connect → Transaction pooler** وانسخ رابط الاتصال ذي المنفذ `6543` إلى إعدادات Vercel الخاصة لاحقًا. استبدل مكان كلمة المرور بكلمتك مع ترميز محارفها الخاصة داخل الرابط. لا تستخدم رابط الاتصال المباشر بدل المجمع دون مراجعة.

## 2. أنشئ مشروع Vercel للتجربة

1. افتح [Vercel](https://vercel.com/new)، وسجّل بحساب GitHub. اختر الخطة **Hobby** للاستخدام الشخصي التجريبي غير التجاري.
2. عند ربط GitHub، امنح التكامل الوصول إلى مستودع `Mzmoh/waraq-invitations` المطلوب فقط حيث يتيح الاختيار ذلك.
3. استورد المستودع إلى مشروع جديد مثل `waraq-trial`. استخدم هذه الإعدادات:

| الإعداد | القيمة |
|---|---|
| Framework Preset | Other |
| Root Directory | جذر المستودع، دون إضافة اسم المجلد المحلي |
| Node.js | 24 |
| Build Command | `npm run build:trial` |
| Output Directory | `dist/vercel` |
| فرع المصدر التجريبي | `engineering/20261124-performance-audit` |

4. في إعدادات Git للمشروع التجريبي، اجعل الفرع المذكور مصدر الدومين الثابت للتجربة بدل دمج الكود إلى `main`. اسم بيئة **Production** في Vercel هنا يخص هذا المشروع المعزول فقط؛ لا يعني إطلاقًا تجاريًا أو ترحيل بيانات إنتاجية.
5. انسخ رابط صفحة مشروع Vercel والدومين الثابت المعروض في **Domains**. استخدم الدومين الفعلي؛ لا تفترض أن الاسم الذي اخترته متاح. إذا لزم نشر أول لإنشاء المشروع فظهور الواجهة وحدها لا يثبت عمل الحسابات أو الحفظ.

## 3. أدخل المتغيرات الخاصة في Vercel

من **Settings → Environment Variables** للمشروع التجريبي. لا تستخدم بادئات `NEXT_PUBLIC_` أو `VITE_` للأسرار.

| الاسم | ما تضعه |
|---|---|
| `WARAQ_TRIAL_ONLY` | `true` |
| `COOKIE_SECURE` | `true` |
| `PUBLIC_ORIGIN` | أصل HTTPS الثابت الفعلي للمشروع، مثل `https://your-trial.vercel.app` دون مسار |
| `DATABASE_URL` | رابط Transaction pooler الخاص بمشروع Supabase التجريبي، منفذ `6543` |
| `SUPABASE_URL` | رابط API لمشروع Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح service role الخاص بالخادم فقط، من إعدادات المشروع |

طبّق المتغيرات على بيئة التجربة التي ستستخدمها، ثم أعد النشر. `WARAQ_TRIAL_PROJECT_REF` مطلوب فقط إن تقرر لاحقًا تشغيل مستورد البيانات الاصطناعية المحمي؛ ليس تصريحًا لهجرة قاعدة بياناتك الحقيقية. لا نضع SQLite في مجلد مؤقت داخل Vercel.

البريد الحقيقي خطوة منفصلة: يحتاج المرسل الموثق وإعدادات Resend الخاصة بالخادم. بدونها سيعرض استرجاع كلمة المرور خطأ إعداد واضحًا؛ لا تعتبره إرسال بريد ناجحًا. لا تشترِ اشتراكًا أو دومينًا لهذه التجربة.

## 4. ما نختبره بعد الربط

نفتح الدومين خارج جلسة مالك Vercel، ونختبر إنشاء حساب تجريبي، دعوة وصورة وصوت، تعديل موعد بغداد، النشر، PIN، رابط ضيف من شبكة أخرى، RSVP، وصلاحيات حساب آخر. إذا طلب الرابط تسجيل الدخول إلى Vercel فهو ليس رابط ضيف عامًا بعد؛ نراجع حماية المعاينة للمشروع التجريبي فقط. لا نُعلن READY بمجرد نجاح Build.

المطلوب منك الآن: إنشاء المشروعين وإرسال رابطَي صفحتيهما فقط. تبقى المفاتيح وكلمة المرور داخل إعداداتك الخاصة. يمكن متابعة الإعداد معك دون كشفها.
