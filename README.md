# وَرَق · استوديو الدعوات

منصة عربية لإنشاء بطاقات إلكترونية متحركة ومشاركتها. اختر المناسبة والقالب وجرّب المقدمة التفاعلية، ثم أضف نصوصك وصورك وحدّد وقت البداية. سجّل الدخول قبل نشر رابط الضيوف.

## التشغيل محليًا

يتطلب Node.js 24 أو أحدث. قاعدة SQLite تُنشأ تلقائيًا عند البداية. إعدادات الخادم موجودة في `.env.example`.

```sh
npm install
npm run dev
```

افتح [http://127.0.0.1:3000](http://127.0.0.1:3000). من لوحة «دعواتي» افتح الرابط المنشور في نافذة خاصة لتجربة الضيف. رابط loopback يعمل على جهاز الخادم. لاستخدامه ضمن الشبكة المحلية شغّل الخادم على `HOST=0.0.0.0` وافتح الصفحة من عنوان الجهاز على الشبكة قبل نسخ رابط الدعوة.

## التحقق

```sh
npm run lint
npm test
npm run build
```

البناء يعيد التحقق من الوحدات والأغلفة ويكتب إصدار Node إلى `dist/`. لاختبار المتصفح ثبّت Playwright أو اضبط `PLAYWRIGHT_MODULE` للإشارة إلى نسخته المثبتة. شغّل خادمًا تجريبيًا على loopback بقاعدة بيانات منفصلة ومرر عنوانه عبر `QA_BASE_URL` قبل `npm run test:e2e`. يمكن تحديد `QA_EVIDENCE_DIR` لحفظ لقطات التحقق. الاختبار ينشئ حسابًا ودعوات في قاعدة الاختبار.

## الاستضافة

يتضمن المشروع `Dockerfile` لتشغيل الخادم بحساب غير root. اربط وحدة تخزين دائمة بـ `/app/var`، وضع الخادم خلف وكيل HTTPS واضبط `PUBLIC_ORIGIN` على النطاق العام. شغّل نسخة خادم واحدة على ملف SQLite، وخذ نسخًا احتياطية عبر واجهة SQLite قبل التحديثات. اضبط بيانات إنشاء المسؤول محليًا عبر `ADMIN_EMAIL` و`ADMIN_PASSWORD` عند التهيئة الأولى ثم احذفهـا من إعدادات التشغيل.

نسخة الاستضافة على Worker تُبنى عبر `npm run build:hosting`. تُطبق migrations من `drizzle/` قبل التشغيل، وتُربط قاعدة D1 باسم `DB`. اختبر العقد محليًا عبر `npm run test:hosting`. تدعم نسخة Worker بيانات تهيئة المسؤول نفسها من إعدادات البيئة. الملفات المخزنة في D1 مرتبطة بضوابط الدعوة وPIN.

تعطلت محاولة رفع المصدر لأن بيئة التنفيذ تعذر عليها حل اسم مضيف مستودع الاستضافة. احتُفظ بنفس هوية الموقع وملفات النشر لاستئناف الرفع بعد استعادة DNS. يمكن تجربة المشروع محليًا الآن.
